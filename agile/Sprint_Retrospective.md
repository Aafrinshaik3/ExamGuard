# ExamGuard - Sprint Retrospective

## 1. What Went Well

- The project was divided into manageable functional modules.
- Examination functionality and monitoring functionality were developed separately and then integrated.
- OpenCV provided the foundation for camera-based monitoring.
- Browser monitoring added additional examination activity signals.
- Weighted violation analysis provided a structured approach to integrity analysis.
- Administrative analytics provided a way to review collected monitoring information.

## 2. Challenges Encountered

- Integrating real-time monitoring with the examination workflow.
- Handling camera-based face detection.
- Managing different types of monitoring events.
- Configuring thresholds and violation weights.
- Integrating multiple application components.
- Testing monitoring functionality under different environmental conditions.
- Managing dependencies required by computer vision and AI-related components.

## 3. Improvements Made

- Monitoring functionality was divided into separate event types.
- Violation weights were configured for different monitoring events.
- Thresholds were introduced to control event detection.
- Administrative analytics were added for reviewing monitoring information.
- Documentation and setup instructions were prepared for reproducibility.

## 4. What Could Be Improved

Future iterations could improve:

- Face detection accuracy.
- Anti-spoofing capabilities.
- Cross-browser compatibility.
- Cross-platform testing.
- Scalability for simultaneous examinations.
- Monitoring accuracy under poor lighting and noisy environments.
- Automated unit and integration testing.
- Analytics visualization.

## 5. Future Action Items

1. Improve face verification and anti-spoofing.
2. Expand automated testing.
3. Improve cross-platform compatibility.
4. Improve analytics.
5. Improve deployment and scalability.
6. Refine monitoring thresholds based on testing.
